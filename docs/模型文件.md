# Chicago 3.0 模型文件

> 版本 0.1.0（2026-11-23）。這份文件說明模型做什麼、怎麼算、根據哪些假設、有哪些限制、怎麼驗證過，以及版本變更。給要審查或使用這個模型的人看：投資委員會、風控、法遵，以及想知道數字從哪裡來的經理人。

## 1. 用途與範圍

**用途：** 為一檔台股股票基金訂出年度的**策略性資產配置（SAA）政策組合**。政策組合以「桶」為單位，例如台積電、其他半導體、金融保險。輸出包括各桶目標權重、再平衡區間、追蹤誤差（TE）預算的分配，以及基金現況和政策的比較。

**適用：**
- 以台股上市股票為主、以**加權股價報酬指數**為指標的主動式股票基金或 ETF。
- 決策層級是桶，不是個股。個股挑選屬於戰術與選股層，不在模型裡。

**不適用：**
- 債券、多資產或海外基金。
- 以其他指數為指標的被動式 ETF（例如臺灣 50）。
- 個股層級的最佳化、日內交易或擇時。

**使用方式：** 模型的輸出是投資委員會討論的**起點**，不是決定本身。政策組合必須經投資委員會核准才能生效（見 `docs/免責聲明.md`）。

## 2. 三層框架

```
指標 B（加權報酬指數，依市值）
  │  結構層：法規、容量造成的偏離（例如台積電最多 25%）
  ▼
可投資中性 N（不違反任何限制、最接近指標的組合）
  │  策略層：投資委員會的觀點（本模型產出）
  ▼
政策 P（年度目標權重＋再平衡區間）
  │  戰術與選股層：經理人
  ▼
實際基金 F
```

每一層各有自己的 TE 和績效歸因。這樣做的好處是能把「法規逼的」「委員會決定的」「經理人做的」分開評估。

## 3. 資料

| 資料 | 來源 | 用途 |
|---|---|---|
| 全市場當日快照：收盤、成交值、發行股數、產業別 | 證交所與櫃買中心 OpenAPI | 市值、股票池、分桶、容量 |
| 個股每日收盤（含漲跌） | 證交所每日收盤行情（MI_INDEX）；連不上時改用 FinMind | 桶的報酬 |
| 除權除息結果 | 證交所除權除息結果表（TWT49U）；備援 FinMind | 把價格報酬還原成總報酬 |
| 加權股價報酬指數 | 證交所（MI_INDEX 內含）／FinMind | 官方指標，用來勾稽 |
| 基金持股 | 投信網站（統一、復華自動下載）或使用者上傳 CSV | 基金現況 |

- **股票池：** 依快照日市值排序，取上市市值前 400 檔（`universe_top_n`）。
- **桶的報酬：** 桶內個股以前一日市值加權的日總報酬。第一天的前一日市值，用當日市值和當日報酬回推。
- **指標權重 w_B：** 計算日（`asof`）各桶市值占比。
- **勾稽：** 用股票池重建的指標，要和官方加權報酬指數比較。單期報酬差距超過門檻（預設 4%）時，命令列版會停止；網頁版會顯示警告，但繼續執行。

## 4. 分桶

設定檔的 `buckets` 區決定分桶規則，依下列優先順序：

1. `single_stock`：單一個股自成一桶（例如台積電）。
2. `overrides`：指定個股歸到某桶（例如把散熱與機構件歸入 AI 硬體零組件）。
3. `by_industry`：依證交所產業別歸桶。
4. 其他歸入 `default`。

預設的 7 桶：台積電、其他半導體、AI 硬體零組件、電腦與伺服器、其他電子、金融保險、傳產與其他。

## 5. 方法

### 5.1 風險模型

- 共變異矩陣 Σ 由估計期間內各桶的日報酬估計，年化因子 250。
- 預設用 **Ledoit–Wolf 收縮**，降低樣本誤差。也可以選樣本共變異，或 EWMA（半衰期 60 日）。
- 預設估計期間是計算日往前 365 個日曆天。
- TE(a) = √(a′Σa)；β = w′Σw_B ÷ w_B′Σw_B。

### 5.2 容量與可投資中性 N

**個股容量** 取以下三者的最小值，以占基金淨資產比例表示：
1. 單一個股上限 × 淨資產：預設 10%，台積電 25%。
2. 已發行股份上限 × 該股市值：預設 10%。
3. 出清天數 × 每日參與率 × 60 日平均成交值：預設 10 天 × 20%。

把個股容量加總，就得到**桶容量**。每桶的上限 = min(桶容量, 設定的桶上限)。

**可投資中性 N：** 從 w_B 出發，把超過上限的桶壓到上限，多出來的權重按比例分給還有空間的桶，反覆調整直到沒有桶超限。N 的性質：權重加總為 1；沒被壓的桶之間，彼此比例不變。

結構層 TE = TE(N − B)。

### 5.3 均衡報酬（反向最佳化）

Π = δ Σ w_B，其中 δ = ERP ÷ (w_B′Σw_B)，預設 ERP 6%。

Π 是「如果市場是對的」時，各桶承擔風險應得的超額報酬。網頁上的預期報酬用的就是 Π；歷史平均只供參考，不能當成預期。

### 5.4 Black–Litterman

觀點的形式是「某桶未來一年對指標超額 q，信心 c（0 < c < 1）」。

- 觀點組合：P_k = e_桶 − w_B。
- 觀點不確定性：Ω_kk = (P_k τΣ P_k′) × (1 − c) ÷ c。
- 混合後的預期：μ_BL = [(τΣ)⁻¹ + P′Ω⁻¹P]⁻¹ [(τΣ)⁻¹Π + P′Ω⁻¹Q]。
- 觀點帶來的超額：α = μ_BL − Π。

**重要性質：** Ω 和 τΣ 成正比，所以 τ 在 μ_BL 裡會完全消掉。也就是說，τ 不影響政策權重，真正控制觀點強弱的是信心 c。τ 保留為參數，只是為了和文獻一致；網頁上已註明。

### 5.5 TE 預算分層

假設各層之間互不相關，平方相加：總 TE² = 結構² + 策略² + 戰術²。

- 策略 TE 上限 = √((總² − 結構²) × 策略份額)。預設總 TE 15%，策略份額 0.5（剩下的空間策略與戰術平分）。
- 政策確定後，留給戰術的空間 ≈ √(總² − 政策 TE²)。

### 5.6 政策最佳化

**目標：** 求主動部位 a = w − N，使 α′a − (λ/2)·TE(a)² 最大，其中 λ = IR ÷ 策略 TE 上限（預設 IR 0.5）。

**限制：**
- 權重加總為 1，且每桶權重 ≥ 0。
- |w − N| ≤ 單桶最大傾斜，預設 15%。
- 固定桶（預設台積電）的權重等於 N。
- TE(w − N) ≤ 策略 TE 上限。
- w ≤ 桶容量。容量低於 N 時，上限改用 N。

用 cvxpy 求解。沒有可行解時會停止，並說明是哪一步。

**沒有觀點時：** α = 0，所以 P = N。模型不會無中生有偏離中性。

### 5.7 預期主動報酬拆解

預期主動報酬 = Beta 溢酬 + 觀點 α：
- Beta 溢酬 = Π′(w − w_B)，恆等於 ERP × (β − 1)。這部分只是把風險加在高 Beta 的桶上，不是判斷力。
- 觀點 α = α′(w − w_B)。

基金現況和每個政策都會做這個拆解，用來判斷預期報酬裡有多少真的來自觀點。

### 5.8 再平衡區間

1. 每桶各自往上、往下移動，移動的資金由其他非固定桶按比例供應，直到策略 TE 增加一個增量（預設 1%）為止。
2. 區間寬度取上述距離和目標權重一半之中較小的一個，再夾在 [2%, 10%] 之間。
3. 已在上限的桶（預設台積電）不往上移。

實際權重在區間內就不動，碰到邊界才再平衡。監控表會列出哪幾桶在區間外，以及回到最近邊界或回到目標各需要多少換手（單向）。

### 5.9 穩健性

- **重抽樣：** 以 20 日為一個區塊，從估計期間的日報酬做區塊自助抽樣（預設 300 次）。每次重估 Σ 並重解政策，看各桶權重的分布，以及落在區間外的比例。
- **觀點敏感度：** 第一個觀點的超額報酬取 0%–10%、信心取 0.25 / 0.5 / 0.75，畫成網格，看政策權重怎麼變。
- **壓力測試：** 把指定的歷史期間重播一次，列出指標、N、P 和基金的報酬與相對報酬。網頁版預設用估計期間內重建指標的最大回檔。

### 5.10 回溯歸因（僅命令列版）

假設過去某一天就採用這個政策，每月再平衡，把基金的實際報酬拆成三層：
- 結構：N − B。
- 策略：P − N。
- 執行：F − P，包含戰術、選股和成本。

另外列出重建指標和官方指數之間的差距。這項分析需要基金自己的價格和配息資料，網頁版沒有。

## 6. 主要假設

1. 市場均衡可以用市值加權的指標代表，CAPM 反向最佳化得到的 Π 是合理的中性預期。
2. 估計期間的共變異可以代表未來一年的風險。
3. 各層 TE 之間互不相關，所以平方可以相加。
4. 觀點之間互不相關，Ω 是對角矩陣。
5. 容量用計算日的市值和 60 日平均成交值估計，未來一年大致不變。
6. 基金持股只看股票部位；權重先正規化成 100% 再分桶，現金、期貨等不計。

## 7. 已知限制

| 限制 | 影響 | 因應 |
|---|---|---|
| 股票池用計算日的前 400 大，回推過去 | 有倖存者偏差：過去下市或掉出前 400 的股票不在裡面 | 以勾稽門檻控管，並在報告揭露勾稽差距 |
| 指標只含上市股票；基金持有的上櫃股票會依產業分到桶裡 | 基金和指標的口徑不完全一致；上櫃比重高的基金，TE 會被高估 | 上櫃比重高的基金解讀時要保留 |
| 單期模型，一年估一次 | 不處理期中的觀點或風險變化 | 期中用區間監控；有重大事件時重新評估 |
| 共變異只用一年資料 | 不包含更長期的危機情境 | 用壓力測試和重抽樣補充 |
| 最佳化不含交易成本 | 政策可能要求較大的換手 | 區間設計和換手報表；成本由執行層評估 |
| 網頁版的部分資料模式 | 股價還沒補齊時，桶報酬和共變異只反映已下載的股票 | 畫面會顯示覆蓋率；資料不完整時的結果只能當測試 |
| 持股來源只自動支援統一、復華 | 其他基金需要手動上傳 CSV | 見使用手冊 |
| 證交所歷史資料只含目前上市狀態下的交易 | 從上櫃轉上市的股票，上櫃期間沒有資料 | 對以上市為口徑的指標而言，這反而是一致的 |

## 8. 驗證

| 項目 | 方法 | 結果 |
|---|---|---|
| 核心計算 | 和 SAA 補充課原始程式比較（凍結的黃金數字） | 誤差 < 1e-6 |
| 端到端 | 只用設定檔從原始資料重算課程案例（00981A 2027） | 政策權重差異 0.0 |
| 手算核對 | 人造 3 桶市場，每一步都可以手算 | 一致；在 CI 每次執行 |
| 指標重建 | 重建指標和官方加權報酬指數比較 | 每期差距低於 4% 門檻 |
| 資料來源切換 | 證交所每日資料和 FinMind 逐筆比較（收盤、漲跌、除權息） | 一致；差別只有少數股票在上櫃期間的資料 |
| 網頁流程 | Streamlit AppTest 無頭測試：從選基金到結果，包含部分資料模式 | 通過 |
| 自動測試 | pytest，共 125 個；GitHub Actions 每次推送都執行 | 全部通過 |

驗證中發現並修正的問題：
- 課程原始程式的壓力測試起日 10/03 是週六。改成一致的重播方式後，相對報酬由講義的 −1.5% / −13.8% 修正為 −1.6% / −13.9%（政策 / 基金）。
- 面板資料第一天的報酬被當成 0。已改成用當日市值和報酬回推前一日市值。
